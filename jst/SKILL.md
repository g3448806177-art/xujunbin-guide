# jst

## 开关

- 新对话默认关闭。用户直接说“使用jst”或明确调用 `$jst` 时开启，说“关闭jst”时关闭；允许空格、英文大小写差异。按整句意图判断：“不要使用jst”不能开启，“不要关闭jst”不能关闭。引用、文件内容和讨论示例不触发开关。
- 开关无需审批，简短确认即可；同条消息带任务时先切换再处理。状态在当前对话持续；重复开启不清空任务、方案或批准记录，不写配置文件。
- 关闭只停用 jst 的附加审批与模型分配规则，不代表批准或取消任务，不自动执行待批方案。其他有效指令仍遵守。
- 在上下文保留开关、待批方案、已批准范围和任务状态；缺失关键记录时核对，不猜测既往批准。

## 开启后：先理解，再审批

1. 新的实质请求先基于对话和已可见材料，说明目标与范围、步骤、交付与完成标准、关键假设或缺失信息。简单任务一段即可，复杂任务保留影响决定的细节；关键条件不清先澄清。明确请求批准后结束本轮。
2. 未批准前不开展业务查询、扫描、文件处理或外部操作，也不委派子体或后台预执行；仅可读取加载指令所必需的规则与技能文件。只批准前置检查时，仅做该检查。
3. “批准”“同意”“yes”“开始”“按这个做”“继续”等明确指向唯一待批方案，且范围清楚、关键条件齐备时，立即进入执行。“不批准”“不同意”等拒绝语不能按关键词误认。补充资料、选择参数、确认理解、沉默或预选项均不是批准；有歧义只问所缺信息，不重复整份方案。
4. 部分批准只做对应部分；修改方案并明确要求执行可按修改后的清晰方案开始。同一已批准任务的继续、验证和修复不再审批；新任务或范围、交付、成本、外部动作的实质变化，才重新审批受影响部分。进度询问、取消、普通寒暄不作为新任务。
5. 用户明确豁免本次审批时直接执行指定范围，并采用下述模型分配规则；不能把催促当豁免。取消即停止对应任务。完成后交付实际结果和必要核验，未完成部分如实说明。

## 每次获批后：按难度分配模型

- 先按子任务的推理难度、歧义、影响和失败代价分级，再从当前工具实际公布的可用模型与推理档位中选择；不猜模型名称、价格或能力。
- 简单、重复、规则明确：轻量模型、较低推理档位。常规分析、文件处理、一般开发：通用模型、适中档位。复杂推理、关键判断、困难排错：高能力模型、较高档位。可用时分别参考 `gpt-6-luna`、`gpt-6.1-sol`、`gpt-6-astra`；名称仅为示例，以当前环境为准。
- 用最少必要子体处理有独立执行或核验价值的工作；极小或不适合委派的任务可由当前代理完成，不为分工硬拆。只并行互不依赖的任务，避免同时修改同一文件。
- 新建子体优先使用最小独立上下文：目标、输入位置、必要约束、已批准范围、交付与验收标准；支持时用 `fork_turns="none"` 并显式传模型/推理档位。不给完整历史，不让子体另起审批循环或扩大授权。
- 执行中根据实际难度或失败调整后续委派的模型；复用已有结果，避免重复劳动。启动时简短说明分工与模型选择即可，无变化不重复报告。
- 环境不支持子体或指定模型时说明实际限制，用现有能力完成获批任务；不能声称已切换模型。技能本身不会切换主对话模型，也不授权安装工具、购买服务或更改设置。
