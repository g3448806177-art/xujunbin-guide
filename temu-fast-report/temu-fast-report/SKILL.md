# TEMU 快速报单

## 执行顺序

提取原表 → 批量SKC记忆查询 → 命中直接复用／未命中网页搜款 → 生成并回读校验报单 → 交付 → 人工决定是否录入记忆。

脚本路径相对于此技能目录。Windows 11 使用含 openpyxl、Pillow、lxml 的 Python；可先通过 Codex 的工作区依赖工具查找可用运行时。仓库中的 `install.cmd` 会把技能装到当前用户的 `.codex/skills`，询问并保存使用者自定义的报单名，并在桌面创建空白记忆表和属性库。
网页操作使用当前可用浏览器工具及其返回的API文档，不能调用旧豆包专用的`bu.*`。

## 1. 提取与记忆查询

```bash
python3 scripts/prepare.py --source "/path/to/Temu备货管理.xlsx" --work-dir ./work
```

报单名由使用者自定义：默认读取安装时写入本技能`config/settings.json`的`reporter`；用户本次指定其他名字时加`--reporter <报单名>`。未设置时prepare报错退出，应先问用户报单名再用`--reporter`重跑，不得自拟。prepare把报单名写入records，build据此填写F列和文件名，`matches.json`无需再写`reporter`。

可选`--order-file`合并半托管订单包裹表；无SKC的订单直接网页搜款，最终SKC列标记“（半托管订单）”。`--attr-dir`可指定属性数据源。时效获取已取消；旧`--stats`参数仅兼容接受并忽略，不读取时效表。

未指定属性目录时，只读取安装时在 Win11 桌面创建的`店铺属性库`文件夹中的 xlsx；显式`--attr-dir`存在时按用户指定目录读取。该文件夹内的`店铺属性库.xlsx`是空白表头，需先手动填入本组可用的商品属性或把结构兼容的导出表放进文件夹；空库不推断属性。属性缓存包含源目录完整路径、各源表修改时间和大小、解析版本，任一变化均重建。每次报单先运行prepare；用户指出属性错误或要求重读时，重新从当前原始库执行prepare，不能沿用旧批次的属性结果。

默认记忆原表：安装时创建的 Win11 桌面`报单记忆.xlsx`；实际桌面路径由安装配置读取。新安装为空表，只有人工录入完整 SKC 记录后才会命中。prepare自动查询，输出：

- `records.json`：原始记录和图片路径。`recordId`区分文件、工作表、源行；`sourceRow`保留原行号。使用记录中的绝对图片路径。
- `search-groups.json`：相同SKC及相同SKU图片共用一组搜索；组内`recordIds`仍须逐条确认颜色、尺码和数量。
- `memory-hits.json`：只含本批命中记录、`memoryCopyByRecord`中的直接复用记录、未命中的网页搜索记录ID，以及耗时和输出字节数摘要。
- `cache/product-attributes.json`、`cache/报单记忆.sqlite`和`manifest.json`：本地处理数据，不整份读入对话。记忆索引默认保存在本次工作目录，不写入记忆原表所在文件夹。

**记忆唯一入口是完整SKC精确相等。** 只使用`record.skcId`；空值、非法值、未命中都直接网页找款。禁止用货号、店铺名、图片相似度、部分数字或其他历史报单补查记忆。不要让模型逐行读Excel或读取整份SQLite索引。

**只要完整SKC命中，就不再搜款、不打开历史链接复核。** 从`memoryCopyByRecord`取优先记录：多条历史记录优先有采购链接、核验时间最新的一条，完整候选仍在`hits`保留。采购记录复制店铺、网页货号、单价和链接；记忆中已有地址直接复用，地址或历史链接为空时照原样留空，不触发补查。本次只使用备货表的`rawSkuCode`、颜色、尺码、数量、SKU图和SKC。网站备注固定重新写为`历史网页货号*本次SKU原始颜色*本次码数*本次数量`，因此同一链接可用于不同SKU货号。命中网购记录则直接放入网购区，不再搜图。只有`webRecordIds`中的未命中SKC按需执行最多两轮搜图。

**记忆库在报单过程中只读。** prepare、build、重试或任何自动流程都不得新增、更新、删除或同步记忆记录。每条需保留的采购、网购或审核记录，必须由人工核对后直接录入`报单记忆.xlsx`；报单结果和“命中”均不等于已获准写入。

命中SKC不读取历史图片；正式报单继续使用本次SKU图。查询、图片提取、人工录入说明和匹配数据格式见 [memory-workflow.md](references/memory-workflow.md)，需要时再读。默认命令只打印摘要，不将全表、全索引或图片编码传入对话。

你删除或修改的记录以最新Excel为准。索引只保存SKC和位置，原表变化自动重建；原表缺失或损坏不能返回旧内容。自动匹配不等于人工确认。

## 2. 网页找款与核对

只对`webRecordIds`中的SKC确认搜款网登录及上传可用。导航`https://sooxie.com/shitu`上传当前SKU图片，确认网页上传控件已接收本次文件且结果列表已更新再读取。上传接口、文件挂载、自动化连接或搜索加载失败均记入`search_failed`并带具体`errorCode`，不能算无同款。`memoryCopyRecordIds`严禁上传或搜索。

### 标签页调度：最多10个搜图页＋2个详情页

- 先将`search-groups.json`与`webRecordIds`取交集形成待搜队列；组内只保留未命中记录。每个不同搜索组占用一个搜图页，相同SKC与相同SKU图共用结果。队列为空时不开网页，不足10组按实际数量开，超过10组分批补位。
- 本批复用同一浏览器会话，最多保留10个搜图标签页和2个共用详情标签页。先在一个搜图页确认登录、上传方式和结果归属，再补齐本批其余搜图页。记录`groupKey → recordIds / 图片绝对路径 / 轮次 / 实际tabId`的对应关系；浏览器ID、控件和API以当前工具文档及页面观察为准，不沿用过期元素编号。
- 开始网页阶段时必须先读取当前浏览器的`file-uploads`文档；Chromium上传异常时再读取`chrome-file-upload-troubleshooting`。当前统一浏览器接口使用`tab.playwright.waitForEvent("filechooser")`和返回对象的`chooser.setFiles(...)`，不能因为屏幕控制层没有文件上传按钮、系统窗口未自动操作或旧工具没有同名方法，就声称当前浏览器不支持上传。
- 首个未命中组兼作上传预检。搜款网`/shitu`当前页面同时存在3个隐藏的`input[type="file"]`，不能使用`locator('input[type="file"]').first()`或直接点击任意隐藏输入框；页面中央“点击上传 / 拖拽图片到此处”的真实触发区是`#txtexcel`。严格按顺序执行：先创建`const chooserPromise = tab.playwright.waitForEvent("filechooser", {timeoutMs: 10000})`，再点击`tab.playwright.locator('#txtexcel')`，随后`const chooser = await chooserPromise`并用`await chooser.setFiles([smallImagePath])`提交绝对路径；第二轮改用`smallMainImagePath`。若`#txtexcel`不存在，先局部检查上传区DOM和控件数量，再选择与可见“点击上传”区域实际关联的控件，禁止退回到第一个通用文件输入框。不能调用不存在的`locator.setInputFiles`、沿用旧`bu.*`接口，也不能把图片地址填入文件控件。缺文件先修复该图，不额外获取图片网址或上传图床。
- 只有在已读取当前文档且实际调用`waitForEvent("filechooser")`仍确认该API不存在时，才可记录`upload_unavailable`。`filechooser`等待超时表示点击目标未触发选择器，优先重新检查`#txtexcel`、遮挡和页面变化，不能据此判断本地文件权限关闭，也不能提示用户修改扩展权限。只有成功取得`chooser`后，`chooser.setFiles(...)`明确因Chrome本地文件权限报错时，才停止整批网页阶段并提示一次：打开`chrome://extensions`，进入ChatGPT浏览器扩展的“详细信息”，开启“允许访问文件网址”；不要把所有未处理SKC逐条写成人工审核。权限修复后从首个未处理组继续。
- Windows“选择文件”窗口不是本流程的上传成功凭据。不得把仅在系统窗口选中图片看作网页已收到文件，也不得继续读取旧结果；由当前浏览器工具提供的文件交接接口完成上传，并核对网页控件状态。
- 全部搜图页共用一个提交队列，同一时间最多一张图片等待搜图完成。前一张的本次结果或明确失败已确认，且距上次发起至少5秒后，才提交下一张；等待期间可核对已保存候选。5秒是可调整的初始间隔，不是网站保证，也不能凭单次成功自动缩短。10个搜图页用于保留和轮转结果，不代表10路同时上传。
- `setFiles`返回不等于网页已收到文件。提交后必须局部确认至少一项与本次文件直接关联的页面证据：上传预览/文件名已更新、文件输入状态显示已挂载，或该组新的搜图请求已经启动；随后还要确认结果属于当前`groupKey + 轮次`。完成上述真实调用后页面仍显示“点击上传”、控件仍为空或仍是旧结果时，才记`upload_not_attached`，不得判无同款；没有调用上传API时不得使用此代码。
- 每轮先局部读取上传状态、结果总数和错误提示，确认本次图片对应的结果已完成更新，再一次保存前5个候选的排序、链接、缩略图和必要字段，按`groupKey + 轮次`归档。通用标题出现或“0件”不能单独证明搜图完成；有“请求过快”、加载中或旧列表时不读候选、不判无同款。同一图片重试不要求候选发生变化。
- 前5限制同时适用于读取与选择：列表在页面侧先截取前5，再返回所需字段；状态检查只读取局部状态元素，不用整页`body.innerText`、整页结果快照或先返回全部候选再截断。必要的页面控件定位应使用最小范围观察，不将第6条及以后的候选带入比较，也不为寻找白名单扩大范围。
- 搜图页保留结果，不在搜图页打开详情。两个详情页循环打开已保存的候选链接：需要对比时分别放候选A/B，配合目标SKU图与`collage.py`核对；只有一个合格候选时不强制再找第二个。两个详情页共用本批URL缓存，同一详情已读取的内容直接复用，目标颜色尺码仍逐条核对。
- 单组核对和证据保存完成后，才将其搜图页分配给下一组；第一轮未确认且有主图时，在原搜图页进行第二轮，并保留第一轮证据。换候选直接使用已保存链接，不因离开结果页而重新上传同一张图。
- 出现“请求过快”立即暂停全部新提交并保留已有结果。先关闭页面的限流提示弹窗，再从限流发生时起冷却至少60秒，在原搜图页对失败图片重试一次；该值是初始退避值，不代表最短恢复时间。上传入口超时先检查弹窗遮挡，不直接认定浏览器权限失效；不以关闭重开标签页、刷新或换会话代替冷却。重试仍限流时将该组记`search_failed`，`errorCode`写`rate_limited`，并停止本批后续网页提交；未执行组记录限流未执行，已就绪结果继续核对。
- 自动化在网页确认文件挂载前或等待新结果期间失去页面/浏览器连接，记`upload_connection_lost`；登录失效记`login_failed`；网页已确认收到文件但结果加载针对性重试一次仍失败，记`search_failed`。这些状态均保留实际原因，不得写入`unmatched`。重试沿用当前轮次，不增加搜索范围；不得为了凑满标签页搜索记忆命中项。

每组最多两轮，每轮只看前5个候选：

1. SKU图前5，缩略图排除明显不符候选，疑似候选在这5条内看详情。
2. 第一轮没有找到可确认的同款，再用链接主图看前5。主图只辅助识别款式，颜色尺码以原表和SKU图为准。
3. 两轮均成功加载并排除候选，归`unmatched`，表述“搜索范围内无同款”。无链接主图只进行第一轮。不看第6条，不进行第三轮。
4. 存在疑似款但关键部位或规格无法确认，归`pending`，不强行采购，也不能声称无同款。

一次提取前5条缩略图、店铺、货号、价格、链接和排序，按`references/preferred-shops.json`标注白名单。同一详情URL本批只读一次；一次提取货号、颜色尺码、当前单价、店铺、URL、多角度图及页面已显示的店铺地址。按浏览器工具允许的资源下载方式保存已观察到的图片。**候选经款式、颜色、尺码和价格核对并选中后，读取该商品详情页已显示的店铺地址并写入采购表H列。** 不为地址另开商家页，也不获取平均发货时间或24/48小时发货率；详情页未显示地址时留空。

硬性核对：鞋型类别、闭合方式、帮高、鞋底厚度及结构、装饰元素（扣带、车线、拼接、冲孔等）必须一致。鞋头、材质辅助判断；颜色可以是同款不同色，但必须确认网页有目标颜色和尺码。页面有尺码选项不能表述为已确认库存。

白名单也须核对通过；多个合格白名单按搜索顺序选。无合格白名单时，选综合排序中第一个核对通过的候选，不按时效或最低价另行排序。店铺名去空格比较；潮旭网批=旭日升一号（义全街95号）。

用`collage.py`拼目标与候选图并排核对，保存候选图及依据。关键部位看不清时看已选范围内的详情图，不能只凭一张缩略图认定同款。

## 3. 匹配数据与出表

`matches.json`按`recordId`分为四种互斥状态：

- `matched`：已搜款核对的采购结果，或完整SKC命中的采购复用结果。复用记录增加`memoryCopy:{skc,ref}`，`verification`使用`source:"memory_skc_copy"`、同一SKC及复用依据；记忆复用的`webColor`必须为本次SKU颜色。网页搜款结果的`webColor`保留网站核对到的颜色，导出网站备注仍必须照抄本次SKU原始颜色。
- `unmatched`：范围内无同款的记录ID列表，或完整SKC命中的历史网购复用结果。搜款记录配套`searchEvidence`轮次；网购复用记录仅写`memoryCopy:{source:"memory_skc_copy",skc,ref}`且`rounds`为空。
- `pending`、`search_failed`：记录ID到对象的映射。`pending`至少含`reason`；`search_failed`至少含`errorCode`和`reason`。新记录的`errorCode`只用`upload_unavailable`（无直接文件输入接口）、`upload_not_attached`（网页未收到文件）、`upload_connection_lost`（上传交接时连接中断）、`search_failed`（网页已收图但结果加载失败）、`rate_limited`（限流重试失败）或`login_failed`（登录失效）。这些代码只细分执行失败，主状态仍为`search_failed`。

每条原始记录必须且只能归入一种状态。旧`sourceRow`键仅在跨文件不歧义时兼容；记忆复用必须写入当前完整SKC和来源单元格，构建程序会阻止不同SKC、颜色未替换或复用后仍搜图的结果。字段示例见 [memory-workflow.md](references/memory-workflow.md)。

```bash
python3 scripts/build.py --records work/records.json --matches matches.json \
  --attr-index work/cache/product-attributes.json --output-dir outputs
```

build先校验输入，再生成并回读检查报单，**不会写入记忆表**。它会在报单旁写`.memory-sync.json`，状态固定为`manual_required`，表示本批记忆记录待人工判断和录入。旧的`memory_store.py sync`命令也会拒绝执行，不能报告记忆已更新。

出表提供`--attr-index`时，当前索引优先于records中预存的属性和旧核验状态；当前索引无命中或冲突时留空，不用旧值补回。prepare生成的索引若源目录已移除、源表已改变或缓存版本不一致，build必须停止并要求重跑prepare。只校验本地属性来源，不为刷新属性打开历史采购链接或重新搜款。

人工录入时保留原表布局和WPS单元格图。同SKC、同供应商、同货号和规格是否更新、其他组合是否新增，以及待审核和搜索失败是否保留，均由人工核对后决定。正式报单原行不合并；缺SKC记录不参与查询索引。

## 固定输出规则与验证

- 正式表沿用`assets/采购单模版.xlsx`，该模板为固定版式基准：左A–L采购，M空白，右N–S网购；A1:L1和N1:S1为分区标题，缩放60%，数据区预设到第151行。正文使用宋体系列20号、居中换行、数据行高116；K列和R列“商品属性”的表头与正文固定为20号，其他黄色表头中左侧18号、右侧20号。列宽和其他排版不得擅自压缩或重排；备货规格出现`45 wide`时码数取`45`。待审核和搜索失败必须保留在Sheet1左侧采购区，填写本次码数、颜色、备货货号、件数、报单名、图片、属性和SKC，但成本、店铺、地址、网站备注及店铺批注一律留空。Sheet2「人工审核」只展示网页搜款后已确认成功的记录，不展示待审核、搜索失败、历史SKC复用或网购记录。
- `rawSkuCode`原文写入，空值留空。数量须正整数，采购成本=网页单价×数量，报单名固定为本批报单名（安装时设置，或prepare时`--reporter`指定）；网站备注=`网页货号*本次SKU原始颜色*本次码数*本次数量`，颜色必须从备货表原样复制，不得改成网页颜色名、简称或其他颜色文本。已确认“卡黑色→卡黑色”“黑色内增高→黑色内增高”“黄色内增高→黄色内增高”，不得把这些值简化为“黑色”或“黄色”。解析规格时不得把颜色标签归一化或截短；除明确的货号、尺码分隔部分外，遇到颜色与功能/款式文字连写、括号说明、范围尺码或多个数字等无法确定边界的格式，先保留原文并向用户确认，不猜测删改，确认后再补充解析规则。网页核对选中结果的地址使用该详情页已显示的地址；记忆复用时，单价、网页货号和已有地址照历史抄写，只有SKU货号、颜色、码数和本次数量来自备货表。
- 属性有SKC时只精确匹配，冲突或无结果留空；无SKC时才按原属性库规则匹配货号。属性逻辑不作为记忆查询的替代入口。只要取到至少一项材料，K/R列都固定写成五行：`鞋面材料`、`鞋面材料（副）`、`内里材料`、`鞋底材料`、`鞋垫材料`。`鞋面材料`本身有两种材料时按来源顺序合并为`鞋面材料：材料1+材料2`并去重，且仅该整行文字使用红色；同一单元格的其他四行保持黑色。属性库中的`鞋面材料（副）`、`副鞋面`和`鞋面（副）`属于独立的副鞋面属性，统一单独输出为`鞋面材料（副）：…`，不得合并进鞋面材料行。属性库缺少该值时保持空白，不补写、不推断。
- 采购按店铺分组，保留所有原记录。正式文件按执行当天自动命名为`{报单名}9月14第一次采购单.xlsx`（报单名为“张三”时即`张三9月14第一次采购单.xlsx`）；只要当天已经输出过正式采购单，下一份就取当前输出文件夹内同日报单的**最大次数加1**，依次为第二次、第三次，绝不回填缺失的较小序号。计数同时识别`第二次`、`第2次`、`{报单名}0914采购单.xlsx`和`{报单名}0914采购单2.xlsx`等新旧名称；输出统一使用中文次数。删除文件后不由缓存补回；`--output-dir`启用自动命名，旧命令中的`--output outputs/{报单名}0914采购单.xlsx`也会自动转换。用户明确给出其他自定义文件名时照该名称输出。
- “人工审核”仅含网页搜款成功记录，每行严格只有三项：目标SKU图、确定店铺商品主图、鞋店名称。网页匹配必须有且只有一个已确认候选，并保存其商品主图供表格嵌图；记忆SKC复用、网购、待审核和搜索失败不进入该表。build自动检查状态覆盖、数量单价、两张图片、选中候选一致性，以及待审核行店铺信息为空，再回读金额、SKU/SKC、行数、锚点、分隔列、批注和Excel错误。结构检查不能代替视觉核对。
- 交付分别汇报匹配、网购、待审核、失败数量及“记忆待人工录入”状态。查询耗时、命中数和返回字节数用本批实测，不估算准确率或承诺固定提速比例。

更多模板字段说明见 [format-spec.md](references/format-spec.md)。

## JIT标签核对（可选）

收到标签照片时，使用`scripts/label_helper.py`的`crop`、`skc`、`template`、`report`子命令，按其`--help`参数执行。根据可见标签识别SKC、颜色尺码和SKU，与正式报单核对；看不清保留待核对，不猜数字。
