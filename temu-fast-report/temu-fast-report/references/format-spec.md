# TEMU 报单格式规范（严格对齐 assets/采购单模版.xlsx，写死不可擅自更改）

## 一、整体布局

报单含**两个工作表**：Sheet1 为正式报单（三行结构 + 左右分区，**M列整列留空做左右分隔**），Sheet2「人工审核」只列出目标SKU图、确认店铺商品主图和鞋店名称（见第九节）。

Sheet1 结构：

- **第1行**：分区大标题。A1:L1 合并="采购"（Songti SC Regular 20号居中）；N1:S1 合并="网购"（同）；M1留空
- **第2行**：左右两侧列表头（黄色 FFFF00；左侧除K2“商品属性”外为18号，K2和右侧均为20号；全部居中换行）
- **第3行起**：数据区，左右两侧都从第3行开始、各自顺序排列
- **左侧（A-L列）**：已匹配鞋款（搜款网找到同款）
- **M列（第13列）**：整列空白分隔，不写值、不加边框、不嵌图
- **右侧（N-S列）**：未匹配鞋款（搜款网找不到，放"网购"区）

> build.py 优先加载 `assets/采购单模版.xlsx` 直接填数据（样式100%一致）；模板缺失时按本规范代码重建。

备货表规格中出现 `45 wide` 这类尺码标记时，`45` 写入码数；`wide` 只作为宽度描述，不并入码数。

## 二、表头定义

### 第1行分区标题（宋体系列20号、居中、无填充；默认行高61）

| 区域 | 合并范围 | 文字 |
|---|---|---|
| 左 | A1:L1 | 采购 |
| 分隔 | M1 | 空 |
| 右 | N1:S1 | 网购 |

### 第2行左侧表头（A2:L2，黄色 FFFF00；除K2外宋体系列18号，K2为20号；默认行高61）

| 列 | 表头 | 说明 |
|---|---|---|
| A | 码数 | 备货表中的尺码（SKU码数），原封不动 |
| B | 颜色 | 备货表中的颜色（SKU颜色），原封不动 |
| C | 备货信息货号 | **备货表SKU货号原封不动**，空值留空，禁止窜改 |
| D | 成本 | 搜款网找到的同款成本（元） |
| E | 件数 | 备货单中的件数，必须为正整数，禁止把0或空值自动改为1 |
| F | 报单名 | **固定为本批报单名**（安装时由使用者自定义，或prepare时`--reporter`指定） |
| G | 店铺 | 搜款网对应的店铺（白名单优先） |
| H | 地址 | 新搜款留空；完整SKC命中时复用历史已有地址，空值不补查 |
| I | 图片 | 内嵌 **SKU图片**，140×140px |
| J | 网站备注 | 格式：`货号*颜色*码数*件数量` |
| K | 商品属性 | 表头和正文固定20号；用SKC长数字在商品详细库查，固定五行：`鞋面材料：…\n鞋面材料（副）：…\n内里材料：…\n鞋底材料：…\n鞋垫材料：…`。鞋面材料本身有两种时按来源顺序用加号合并，如`鞋面材料：织物+PU`，该整行标红；副鞋面属性独立填写在`鞋面材料（副）`行；缺项保留空值，无记录整格留空 |
| L | SKC | 只填完整SKC_ID；缺失留空，半托管订单填“（半托管订单）”，禁止用货号替代SKC |

### 第2行右侧表头（N2:S2，黄色 FFFF00、宋体系列20号、默认行高61）

| 列 | 表头 | 说明 |
|---|---|---|
| N | 码数 | 同左侧 |
| O | 颜色 | 同左侧 |
| P | 备货信息货号 | 同左侧（原封不动，空留空） |
| Q | 图片 | 内嵌 SKU 图片，140×140px |
| R | 商品属性 | 同左侧，表头和正文固定20号 |
| S | SKC | 同左侧 |

右侧无成本/件数/报单名/店铺/地址/网站备注列。

## 三、样式规范

- 分区标题（第1行）：Songti SC Regular 20号、水平垂直居中、无填充；工作表默认行高61
- 左表头（A2:L2）：除K2外使用 Songti SC Regular 18号，K2使用20号；右表头（N2:S2）使用20号；均居中、自动换行、黄色填充 FFFF00；M2黄色无边框
- 数据单元格：Songti SC Regular 20号、水平垂直居中、自动换行
- 商品属性列：K列和R列的表头与正文均固定为20号
- 边框：表头及非图片数据单元格使用thin边框；**M分隔列不加边框**
- 数据行高：116；模板预设第3–151行，超出时复制第3行格式
- 工作表缩放：60%，不冻结窗格，不设筛选
- 列宽（精确对齐模板）：A15.4903846153846 B10.5961538461538 C22.4326923076923 D13.6153846153846 E9.875 F17.625 G25.875 H32 I22 J25.0961538461538 K30.1730769230769 L32.1442307692308 M16 N14.7019230769231 O15.4038461538462 P18.0961538461538 Q20.7980769230769 R41.6538461538462 S40.4038461538462

## 四、G列店铺批注（每条已匹配鞋款必须有）

build 按 matches.json 的 `whitelist` 字段自动区分两种措辞：

**白名单胜者（whitelist=true）**：
```
来源URL: https://xxx.sooxie.com/detail/xxx
网页货号: Q2
白名单店铺，鞋型核对一致直接选取
```

**非白名单胜者（whitelist=false，综合排序选取）**：
```
来源URL: https://xxx.sooxie.com/detail/xxx
网页货号: Q2
非白名单·综合排序选取
```
批注宽度320，高度130。不获取时效，不附加时效批注；旧匹配数据中的时效字段也忽略。

## 五、图片嵌入

- 使用 OneCellAnchor 锚定到 **I列（左侧，col=8）或 Q列（右侧，col=16）**
- 图片尺寸 140×140 像素
- **报单内嵌的是 SKU 图**（备货表"SKU图片"列，颜色与下单一致）；链接主图只用于搜图，不嵌入报单
- 图片来源：备货表xlsx中嵌入的商品图（从 xl/media/ 提取）
- 搜图上传图须先缩放到≤1000×1000（prepare 已生成 images-small / images-main-small，直接用）

## 六、不变规则（写死，违反即错误）

1. **备货信息货号（C列/P列）原封不动**：等于备货表中的SKU货号，None→留空，禁止修改、拼接、推断
2. **网站备注（J列）用找到鞋款的货号**：格式 `网页货号*网页颜色*码数*件数`，网页颜色用搜款网商品页的颜色选项名（与目标颜色对应者）
3. **报单名（F列）固定为本批报单名**：安装时由使用者自定义，可用`--reporter`临时指定，不得自拟
4. **商品属性优先用SKC_ID长数字（11位）查询**，不是SKC货号（短货号，不唯一会歧义）；备货表确无SKC_ID时才用货号兜底，唯一命中才填，歧义/无记录一律留空
5. **先按完整SKC查询记忆**，完整SKC命中后直接复用，不打开历史链接、不看历史图、不上传搜图；地址或链接为空也不补查。只有`webRecordIds`中的未命中记录走 `/shitu` 全站以图搜款；不用货号补查。详情仅限每轮前5候选，款式或规格拿不准归“待审核”，不强行采购或当作无同款。
6. **两轮搜图（每轮只看前5）**：第一轮用SKU图看前5缩略图，没有鞋型一致款时第二轮用链接主图再看前5；**两轮前5都明显不匹配直接放右侧网购区**，不翻第6条以后、不搜第3轮
7. **链接主图仅用于提升识别/搜图成功率**：其颜色可能与SKU图不同，报单的颜色、规格等信息**严禁参考主图**，一律以SKU图和备货表为准
8. **白名单候选缩略图一致+8项核对通过直接选**（matches.json 标 whitelist=true），不开非白名单对比；**非白名单直接按搜图综合排序选第一个核对通过者，不再做时效表对比**
9. **搜款网找不到的鞋放右侧网购区**，不强行匹配
10. 两轮成功加载且无同款时表述“搜索范围内无同款”；待审核、上传接口不可用、文件未挂载、自动化连接中断、登录或加载失败不属于网购结果。
11. **潮旭网批=旭日升一号**（同店别名，地址义全街95号）
12. **文件名格式**：`{报单名}{M}月{D}第{中文次数}次采购单.xlsx`。当天没有正式报单时从“第一次”开始；只要当天已经输出过一次，下一份按当前输出文件夹内同日报单的最大次数加1，不回填空缺序号。计数兼容旧的`第2次`和`{报单名}MMDD采购单2.xlsx`等名称，输出统一使用“第二次、第三次”等中文次数且不覆盖已有文件。
13. **省词元操作**：遵守 [SKILL.md的上传与调度规则](../SKILL.md)：最多10个搜图页保留结果，2个详情页循环核对；搜款网通过`waitForEvent("filechooser") → 点击#txtexcel → chooser.setFiles(绝对路径)`提交本地图片，不点击页面上的第一个隐藏`input[type=file]`，不把仅在系统文件窗口选中图片视为上传成功。首个未命中组同时完成上传预检；只有`setFiles`明确报本地文件权限错误时才提示Chrome扩展设置，`filechooser`超时只检查上传控件。上传后先验证网页控件已收到本次文件，再等待本轮结果；全局单张在途并控制提交间隔，限流先关闭提示并冷却后原页重试。状态只局部读取，每轮列表只返回前5个候选，不读取整页候选文本。记忆批量精确查询，只读命中摘要，按需取图；同详情URL本批不重复读，按浏览器允许的方式保存图片，用collage并排核对。
14. **必出 Sheet2「人工审核」**：只展示网页搜款后已确认成功的记录，每行仅含目标SKU图、确定店铺商品主图、鞋店名称三项；待审核和搜索失败留在Sheet1且店铺信息为空

## 七、属性库查询

- **属性库目录**：prepare 默认只读取安装配置指定的桌面`店铺属性库`目录内的 xlsx；可用`--attr-dir`显式指定其他目录。新安装的空白表只有表头，没有属性记录；属性缺少时留空
- **新库表结构**（sheet"上新周期列表数据明细"）：关键列 `SKC_ID`（11位长数字，唯一，主键）、`SKC货号`（不唯一）、`商品属性`（多行文本，识别"鞋面材料：/鞋面材料（副）：/内里材料：/鞋底材料：/鞋垫材料："，并兼容旧名"副鞋面：/鞋面（副）："）、`SKU货号`；同一SKC仅首行有SKC_ID和商品属性，其下SKU行留空（prepare自动向下填充）
- **匹配优先级（双轨）**：①优先用备货表的 **SKC_ID长数字精确匹配**（用户规则，唯一不歧义）；②备货表无SKC_ID时，用SKC货号/SKU货号兜底——唯一命中才填，多个不同材料（ambiguous）或查不到一律留空，禁止瞎填
- 输入兼容鞋面材料/鞋面材料（副）/副鞋面/鞋面（副）/内里材料/鞋底材料/鞋垫材料；输出固定为鞋面材料/鞋面材料（副）/内里材料/鞋底材料/鞋垫材料五行。鞋面材料字段内有多个值时按来源顺序用加号合并并去重，如`织物+PU`，整条鞋面材料行标红，其他四行保持黑色；鞋面材料（副）/副鞋面/鞋面（副）映射到独立的鞋面材料（副）行，不与主鞋面材料合并；取到任一材料时五行都输出，缺项留空，不补写、不猜写
- prepare阶段生成缓存`work/cache/product-attributes.json`，签名包含源目录完整路径、源表修改时间与大小、解析版本；源目录或内容变化后重建。build显式提供当前索引时以索引为准，不能被records中的旧属性覆盖；过期索引必须先重跑prepare

## 八、地址留空与记忆复用

- 已取消时效与地址获取：不读取或搜索本地时效表，不从网页提取平均发货时间、24/48小时发货率或店铺地址，也不为这些字段打开额外页面。
- 新搜款记录的`address`可省略或留空；H列和其余模板布局保持原样，地址为空不阻止出表。
- 完整SKC命中后直接复用采购或网购记录，不打开历史链接、不再搜图；历史已有地址直接复制，空地址、空链接均保留为空。
- 旧`--stats`参数仅兼容接受并忽略。`merchant-stats.json`仅输出`status: disabled`的空兼容结果，不读取旧时效缓存。

## 九、Sheet2「人工审核」三项信息表（build 自动生成）

只展示网页搜款后已确认成功的记录；记忆SKC复用、网购、待审核和搜索失败均不写入本表。待审核和搜索失败改保留在Sheet1左侧采购区，店铺、地址、成本、网站备注及店铺批注全部为空。

- 工作表名固定 `人工审核`，位于 Sheet1 之后；第1行表头（浅蓝 D9E1F2 加粗，行高22），数据从第2行起、行高115
- 列定义（仅3列）：

| 列 | 表头 | 内容 |
|---|---|---|
| A | 目标SKU图 | 内嵌目标SKU图片，100×100px（0-based col=0） |
| B | 确定店铺商品主图 | 已确认选中候选的商品主图，100×100px（0-based col=1） |
| C | 鞋店名称 | 已确认匹配的店铺名称 |

- 网页成功匹配必须在 `matched.<记录键>.candidates` 中恰有一条 `chosen: true`，并提供其 `image` 本地绝对路径作为已确认商品主图；文件缺失时停止生成并补齐图片，不得留空或改用未确认候选图
- 图片统一 OneCellAnchor、100×100px；两张图片与鞋店名称按同一行对齐，全部单元格 thin 灰边框 BFBFBF
